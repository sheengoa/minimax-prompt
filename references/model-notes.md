# 模型速查：双变体、参数边界、Context-IR、试错策略

依据 docs/h3-platform-doc.md（平台文档）与 H3 仓库 README 提炼。写词前对照参数边界，交付前对照变体能力。

## 双变体对比

| 维度 | MiniMax-H3 | MiniMax-H3-Max |
|---|---|---|
| 定位 | 全能基础模型（官方开源权重） | fal.ai 在 H3 上后训练、针对高速生成优化 |
| 功能模式 | T2VA / I2VA / FL2VA / L2VA / Ref2VA 全支持 | 仅 T2VA / I2VA（Ref2VA"coming soon"） |
| 时长 | 4–15s（仅整数） | 5–15s（仅整数） |
| 分辨率 | 768P / 2K（2K 走重生成管线） | 480P / 768P |
| 通用规格 | 24 FPS；32 kHz 立体声原生音频；常见画幅 + adaptive | 同左 |

选择口诀：要参考生成/首尾帧 → 只有 H3；纯文生/图生求快 → H3-Max 可选；犹豫 → H3。

## 能力画像（选型与预期管理）

**强项**（实测与评测一致）：
- **指令式编辑**：视频编辑能力评测第一——改局部、换元素、删物体、加特效不用整条重生成，"90% 满意修一处"的首选模型。
- **文字渲染与视觉包装**：Logo 演绎、花字动效、动态海报、片头字幕专项优化，中英文字形稳定性在视频模型里属第一梯队；数千词级长提示词的快切蒙太奇也能逐镜执行。
- **参考一致性**：Omni Reference 下人物跨镜一致性表现突出；参考素材混搭类型越全（图+视频+音频一起给），一致性越高。
- **口型同步**：人物图 + 音频参考可生成高精度唇形同步（数字人/口播场景可用）；超长对话的一致性尚待验证，口播建议控制在单次 15s 内。

**弱项**（写词时主动绕开）：
- 高张力影视镜头、极限运镜的冲击力弱于专精"前期拍摄"的模型——这类需求提前与用户对齐预期。
- 极小的画面文字（小标签、小字号参数）仍易崩——重要小字建议后期叠加。
- 复杂人群调度、快节奏多主体动作容易乱——减同框人数、拆动作、一镜一事。

## 参数硬边界（写词前核对）

- **时长**：4–15s，只收整数；需求 >15s → 多段拼接（formulas.md）。
- **提示词**：≤7000 字符（结构化六段式远用不满，无需压缩台词）。
- **参考图**：≤9 张；宽高 256–5760（首尾帧图）；宽高比 2:5–5:2；单张 ≤30MB；JPG/JPEG/PNG/WEBP/HEIC/HEIF。
- **参考视频**：≤3 段；每段 2–15s；总时长 ≤15s；≤50MB/段；H.264/H.265。
- **参考音频**：≤3 段；每段 2–15s；总时长 ≤15s；≤15MB/段；WAV/MP3。
- **混合素材**：合计 ≤12 个文件；请求体 ≤64MB（大素材用 URL）。
- **画幅 ratio**：文生视频必填且不能为 `adaptive`；图生视频恒为 `adaptive`（由输入图决定）。
- **分辨率档**：768P 短边默认 768px；2K 不直接生成，走 H3-Regenerate-2K 重生成。

## H3-Context-IR（提示词增强）

- 官方托管的输入理解与精炼系统：解析多模态输入间关系 → 补足缺失语义 → 序列化为 H3-Base 易于理解的结构化表达（即官方指南里的字段结构）。
- **官方强烈建议**生成管线接入 Context-IR，或按 Prompting Guidance 自建等价处理——本 skill 产出的提示词就是该结构的手写等价物。
- API 用法：先创建 `task_type=h3_context_ir` 的异步任务，从 `content.prompt` 取增强后的提示词，再拿去做视频生成；该端点只产提示词不产视频。
- 用户自己用 API/工作流时：提示词写好 → 建议 Context-IR 增强一次 → 生成。网页创作台用户跳过此步。

## 2K 重生成（H3-Regenerate-2K）

- 768P 成片 + 原始上下文（复现原 `content`）+ 恰好一个 `role=base_video` 的视频项 → 重生成 2K 版本。
- 交付时注明：2K 不是直接生成档位，预算允许时用重生成提升细节；重生成也吃原提示词质量——先把 768P 版验证过关。

## 试错策略

- **抽卡成本低**：单次 4–15s、768P，重试代价小——关键动作/风格没把握时，先出短版（如 4–5s）验证主体与风格，通过后再出全长版。
- **简单需求可 one-shot**：促销、口播、简单产品展示类，一条干净提示词往往一次出片，无需抽卡；复杂多镜需求才走"短版验证 → 全长"。
- **一次只改一个变量**：台词/运镜/风格/时长逐项改，否则无法归因；保留提示词版本，便于回滚对照。
- **小瑕疵不整条重试**：用指令编辑修对应处（H3 编辑能力是强项）——"把背景换成暖灰色，保持人物不变"，通常一两轮修到位；只有整体方向不对才重写正文。
- **失败阶梯**（通行做法）：重申参考特征与锚点重试 → 缩短时长/减动作/拆镜 → 换参数（画幅/分辨率）→ 与用户对齐降需求。
- **素材没生效**：先查 `subject_definitions` 特征清单与 `retention_analysis` 标记是否如实，再查上传顺序与标签编号是否一致——标签正确性优先于改词。
- **参考图质量**：人物参考用 1024px 以上、背景干净、光照均匀的图；一张好的 3/4 侧面肖像常胜过五张平庸角度；多角度角色表与分镜参考图分开上传，不要让同一批图兼任两种角色。

## 中文提示词与格式容忍度

- 官方规范要求正文英文（与 Context-IR 输出结构对齐），本 skill 默认照此交付；但平台端实测中文自然语言提示词的指令遵循与文字渲染并不弱于英文——用户明确要中文快写、或在海螺界面快速试小样时，可用中文直写，正式交付仍回英文结构。
- 中文直写时的等价写法：标签写「图片1」「音频1」（对应 `<Picture 1>`/`<Audio 1>`，上传顺序对应编号）；切镜写「0-3秒：…」时间块；一致性写「使用图片1作为唯一人物依据，保持人物身份、脸部、服装、发型、造型完全一致」；风格可列举对标（「整体风格参考《银翼杀手2049》，黑色未来主义，红色警示光，透明 HUD 界面」）。
- 格式容忍度：除官方字段结构外，实测自由段落 + 方括号时间块（`[0 to 2 seconds] …`）也能稳定驱动多镜叙事——字段结构仍是官方基准与交付默认，容忍度只作为快速试错的余地。

## 预期管理与留白

以下领域**无充分口径，留白不编造**，实测后补充：

- 稳定性甜点区量化（每镜时长/镜数/主体数的精确安全上限）——templates.md 节拍速查是官方经验值起步口径，越界表现需自测。
- 多说话人上限、长对话口型一致性：单场景 2–3 人已验证稳定，更多说话人按失败诊断逐项处理。
- 网页创作台（海螺 AI）对完整结构化字段的接受度：官方 skill 即按可粘贴长文本设计，实测长提示词（含数千词英文快切蒙太奇）可正常驱动；但界面表单可能裁剪参数（画幅/时长在 UI 里选）——交付时平台设置行照常给出，UI 有该参数就以 UI 为准。

## 维护基准

- 参数边界与 H3/H3-Max 强绑定，模型迭代后以 docs/ 存档与官方文档站为校对基准同步修订。
- 官方两份指南原文（docs/h3-prompt-guide-*.txt）是字段结构、指令句式、标签规则的唯一权威；本 skill 与其冲突处以原文为准。
